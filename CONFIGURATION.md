# Configuration Guide for esp-heatshrink

This document provides detailed information about configuring the heatshrink library for use as an ESP-IDF component.

## Overview

As of version 2.x, all configuration for this library when used as an ESP-IDF component is managed through **Kconfig**. This means you configure the library using `idf.py menuconfig` instead of editing source files.

## Configuration via menuconfig

### Accessing Configuration

1. Open your ESP-IDF project
2. Run `idf.py menuconfig`
3. Navigate to: **Component config → heatshrink**

### Available Options

#### Memory Allocation Mode

Choose between dynamic and static memory allocation:

- **Dynamic allocation (malloc/free)** [Default]
  - Enables runtime configuration
  - Provides `heatshrink_encoder_alloc()` and `heatshrink_decoder_alloc()` functions
  - Window and lookahead sizes can be configured at runtime
  - Suitable for applications with flexible memory requirements

- **Static allocation (compile-time buffers)**
  - Uses fixed-size buffers configured at compile time
  - Disables alloc/free functions
  - More predictable memory usage
  - Suitable for embedded systems with strict memory requirements
  - Requires configuring static parameters (see below)

#### Static Allocation Parameters

These options are only visible when **Static allocation** is selected:

- **Static window size (2^N bytes)** [Default: 8]
  - Range: 4-15
  - Determines how far back in the input the encoder searches for patterns
  - Value of 8 = 256 bytes, 10 = 1024 bytes, etc.
  - Larger values improve compression but use more memory

- **Static lookahead size (2^N bytes)** [Default: 4]
  - Range: 3-14 (must be less than window size)
  - Determines maximum length of repeated patterns
  - Value of 4 = 16 bytes
  - Should typically be window_size/2 for best results

- **Static input buffer size (bytes)** [Default: 32]
  - Range: 1-4096
  - Size of decoder input buffer
  - Larger values allow more efficient processing but use more memory

#### Performance Options

- **32-bit optimizations** [Default: Enabled]
  - Uses optimized 32-bit code paths
  - On ESP32-S3, automatically enables SIMD instructions (PIE)
  - Can provide 3-20x performance improvement
  - Requires architecture that supports unaligned 32-bit reads

- **Use index** [Default: Disabled]
  - Enables indexing for faster compression
  - Increases memory usage by ~3x (adds 2^(window_size+1) bytes)
  - Can speed up compression by 10-20x
  - Allocates 512 bytes on stack during index construction
  - Recommended only when compression speed is critical

#### Debugging

- **Enable debugging logs** [Default: Disabled]
  - Enables verbose debug output
  - Useful for troubleshooting compression/decompression issues
  - Adds overhead; only enable when debugging

## Configuration Persistence

Configuration is saved in `sdkconfig` in your project directory. This file is automatically generated and should typically be added to version control for your project.

You can also create `sdkconfig.defaults` to specify default configuration values for your project:

```ini
# Example sdkconfig.defaults for heatshrink
CONFIG_HEATSHRINK_DYNAMIC_ALLOC_ENABLED=y
CONFIG_HEATSHRINK_32BIT=y
CONFIG_HEATSHRINK_USE_INDEX=n
CONFIG_HEATSHRINK_DEBUGGING_LOGS=n
```

## Example Configurations

### Configuration 1: Balanced (Recommended for most uses)
```
- Allocation Mode: Dynamic
- 32-bit Optimizations: Enabled
- Use Index: Disabled
```
Best for applications with flexible memory and good performance needs.

### Configuration 2: Maximum Performance
```
- Allocation Mode: Dynamic
- 32-bit Optimizations: Enabled
- Use Index: Enabled
```
Best when compression speed is critical and RAM is not constrained.

### Configuration 3: Memory Constrained
```
- Allocation Mode: Static
- Static Window Bits: 8 (256 bytes)
- Static Lookahead Bits: 4 (16 bytes)
- Static Input Buffer: 32 bytes
- 32-bit Optimizations: Enabled
- Use Index: Disabled
```
Best for embedded systems with strict memory requirements.

### Configuration 4: Better Compression Quality
```
- Allocation Mode: Static
- Static Window Bits: 12 (4KB)
- Static Lookahead Bits: 6 (64 bytes)
- Static Input Buffer: 64 bytes
- 32-bit Optimizations: Enabled
- Use Index: Disabled
```
Better compression ratio but uses more memory.

## Non-ESP-IDF Builds

If you're building this library outside of ESP-IDF (e.g., for testing), the library automatically uses sensible defaults. You can override configuration by defining macros before including the headers:

```c
// Example: Configure for static allocation
#define HEATSHRINK_DYNAMIC_ALLOC 0
#define HEATSHRINK_STATIC_WINDOW_BITS 10
#define HEATSHRINK_STATIC_LOOKAHEAD_BITS 5
#define HEATSHRINK_STATIC_INPUT_BUFFER_SIZE 64
#define HEATSHRINK_32BIT 1
#include "heatshrink_encoder.h"
#include "heatshrink_decoder.h"
```

## Migration from Previous Versions

If you were previously editing `heatshrink_config.h` directly:

1. **Remove any manual edits** to `heatshrink_config.h` (they will be ignored in ESP-IDF builds)
2. Run `idf.py menuconfig`
3. Navigate to **Component config → heatshrink**
4. Configure your settings
5. Save and exit

The library will now use your Kconfig settings automatically.

## Troubleshooting

### My configuration changes aren't being applied

1. Make sure you've saved the menuconfig settings (it will write to `sdkconfig`)
2. Clean your build: `idf.py fullclean`
3. Rebuild: `idf.py build`

### I want different settings for different build configurations

Use `sdkconfig.<profile>` files and specify them with:
```bash
idf.py -D SDKCONFIG=sdkconfig.production build
```

### How do I see what values are actually being used?

You can check the generated `build/config/sdkconfig.h` file to see all `CONFIG_*` defines.

## Testing Configuration

A test script `test_kconfig_integration.sh` is provided to validate that the configuration system works correctly. Run it to verify:

```bash
./test_kconfig_integration.sh
```

This tests various configuration scenarios including non-ESP-IDF builds, ESP-IDF builds, and different allocation modes.
